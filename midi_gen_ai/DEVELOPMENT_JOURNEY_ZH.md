# MIDI AI 续写项目开发历程（课设报告素材）

## 1. 项目背景与目标

本项目是课程设计中的 AI 续写子任务，目标是在 MAESTRO 数据集上训练可用的钢琴 MIDI 续写模型，并逐步走向嵌入式端实时应用。

核心要求分三层：

1. 能生成可听、可辨识的节奏与旋律片段。
2. 能在工程上稳定复现（训练、推理、试听、评估链路完整）。
3. 为后续 ESP32/USB-MIDI 实时接入预留可落地路径。

## 2. 第一阶段：钢琴卷轴（piano-roll）方案

### 2.1 初始方案

早期采用 frame-level 预测：

- 输入：每帧 127 维钢琴卷轴。
- 模型：小型 LSTM（`TinyLSTM`）。
- 目标：预测下一帧 piano-roll（BCE loss）。

该阶段解决了从数据加载到训练、到生成试听的完整闭环。

### 2.2 工程实现亮点

- 构建了 MAESTRO 数据集窗口化 dataloader。
- 提供了训练脚本、导出脚本、试听脚本。
- 引入了分组 batch 采样，减轻跨文件窗口混杂。

### 2.3 遇到的核心问题

尽管 loss 能持续下降，但听感问题突出：

1. 容易出现“同质化重复”和“机械短句循环”。
2. 续写经常进入长音/静默后再复活的模式。
3. 指标和听感存在偏差：低损失不代表音乐性更好。

本质上，frame-level 稀疏预测很容易学习到“高频但不总是合理”的局部统计规律。

### 2.4 放弃前最后结果（旧线）

旧线最后主要 run 为：

- `runs/lstm_longwin_24fps/`

该 run 可视为旧路线收尾版本，后续改为事件序列重写。

## 3. 第二阶段：事件序列重写（active line）

### 3.1 架构转向

将表示从 piano-roll 改为 event token 序列：

- `NOTE_ON`
- `NOTE_OFF`
- `TIME_SHIFT`
- `VELOCITY`

模型仍用 LSTM，但任务变成 next-token 语言建模。

### 3.2 为什么重写

1. 事件表示更接近音乐事件本体，减少无效稀疏帧。
2. 更符合符号音乐建模常见实践。
3. 便于控制生成长度、节奏密度与采样策略。

### 3.3 关键实施

- 完成 tokenizer、dataset、model、train/generate/evaluate 全链重建。
- 加入 token 磁盘缓存与 memory-map 加速重复训练。
- 支持更细致的生成约束（如最小新增秒数）和采样参数扫描。

## 4. 真实开发中的挫折与试错

### 4.1 过拟合与“指标错觉”

发现典型现象：

- `best val loss` checkpoint 并不一定听感最好。
- 某些“过拟合看起来更重”的 checkpoint 反而音乐结构更可听。

结论：

- 不能只靠 loss 做唯一模型选择标准，必须引入听感评测与行为诊断。

### 4.2 生成塌陷问题

多次出现的失败模式：

1. 长音卡死。
2. 长静默（死寂）。
3. 死寂后复活，但进入机械重复短句。

这在 v1/v2 都观察到，只是强度不同。

### 4.3 关于成因的关键思考

通过对比实验形成如下认识：

1. 模型学到了“留白”这个真实演奏特征。
2. 但该特征在某些条件下被过度触发，形成高置信吸引子。
3. prompt 结构（尤其长音收尾）和解码参数会共同放大该问题。

即：这是“模型能力 + 解码策略 + prompt 分布”三者耦合问题，不是单点故障。

## 5. 本阶段方法论沉淀

1. 先保留“可用基线”，再做激进尝试。
2. 所有结论必须通过同 prompt、同参数的 A/B 对比验证。
3. 区分训练问题与解码问题：
   - 模型不变，改解码看是否复现同类故障。
4. 区分模型问题与 prompt 问题：
   - 参数不变，换 prompt 看是否仍塌陷。

## 6. 当前可用于汇报的成果

1. 旧线（piano-roll）可复现试听样本。
2. 新线（event-LM）完成训练、生成、评估、缓存优化闭环。
3. 明确识别并量化了“长音/静默塌陷”问题。
4. 形成了阶段性可解释结论与后续改进方向。

## 7. 对课设报告可直接使用的结论

1. 本项目已跨过“能否生成音乐”的门槛，进入“提升稳定性与可控性”阶段。
2. 主要挑战不再是代码可运行，而是生成行为鲁棒性。
3. 事件序列路线相较旧 frame 路线更有工程延展性，适合后续实时接入。

## 8. 下一步（与主项目联动）

进入 USB-MIDI 端口接入与实时续写阶段，重点不是再无止境压 loss，而是：

1. 低延迟实时推理链路。
2. 稳定 prompt 管理与上下文更新。
3. 约束解码防塌陷（避免长静默/心跳循环）。
4. 端侧资源与延迟权衡（参数量、量化、缓存策略）。
